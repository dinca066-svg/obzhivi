# Обживи

Прототип сервиса: план квартиры → спальня в масштабе → мебель из каталога → 3D-ракурс → дизайн Seedream → ссылки на товары.

**Тестовый сайт:** https://obzhivi-furniture-catalog-dina.dina-1.chatgpt.site  
**Инструкция тестировщику:** https://obzhivi-furniture-catalog-dina.dina-1.chatgpt.site/test.html

Репозиторий приватный. Сайт доступен без входа. API-ключи не входят в исходники.

## Что работает

- Загрузка JPG, PNG, WebP, PDF; выбор страницы; предварительный поиск прямоугольных областей по линиям стен, выбор спальни кликом и ручная коррекция.
- После выбора спальни: локальное OCR площади (Tesseract, русский язык, совпадение минимум двух чтений), оценка масштаба по площади и контуру, поиск двери и окон по линиям стен; переход сразу к мебели. Если площадь не читается, запрашивается одно значение.
- Исправление распознавания доступно отдельно. Высоты потолка, двери, окон, подоконник, петли и открывание — явно отмеченные предположения, а не результат чтения плана.
- Кровать Shane и тумбы GRV: реальные GLB, фотографии, габариты, ссылки продавцов. Перетаскивание и поворот на предмете, проверка пересечений.
- 3D-комната из размеченного плана. Закрытая дверь. Подбор камер 3:4 с ровным горизонтом, экспорт RGB / глубины / масок.
- Серверный запрос Kie Seedream 5.5: четыре варианта стиля, пожелания, история, сравнение с исходным кадром, обратная связь.

Автораспознавание пока рассчитано на чёткие прямоугольные планы с площадью в м², одним дверным проёмом и окнами с параллельными линиями. Неоднозначные проёмы не превращаются молча в глухую стену: предлагается более чёткий план или ручное исправление. Произвольные обозначения БТИ, перспектива фотографии, непрямоугольные комнаты, шкафы, ранжирование поставщиков и вся квартира в 3D пока не реализованы. Генератор может менять геометрию: его результат не является источником размеров. GLB из Meshy — модель для примерки, а не точная заводская геометрия.

## Разработка

Node.js 22.13+ (рекомендуется 24 LTS), npm.

```sh
npm ci
cp .env.example .dev.vars
# Заполнить KIE_API_KEY локально. Не добавлять файл в Git.
npm test
npm run build
# Только для новой локальной базы:
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_familiar_tony_stark.sql
npm start -- --port 8781
```

`npm start` запускает собранный Worker с локальными D1/R2. Для правок интерфейса пересоберите проект; `npm run dev` — режим разработки Vite. Локальный URL не доступен Kie: для реальной генерации требуется опубликованный сервер с доступной ссылкой на кадр.

## Устройство проекта

- `src/` — интерфейс, геометрия, расстановка и Three.js-сцена.
- `server/` — API, гостевые сеансы, задания генерации и адаптер Kie.
- `db/`, `drizzle/` — схема D1 и миграции.
- `public/` — GLB, фотографии, демонстрационный план.
- `worker/`, `app/`, `lib/`, `scripts/` — серверный шаблон Sites / Vinext и сборка.
- `tests/` — геометрия, модели, камеры, авторизация, idempotency и адаптер провайдера.
- `docs/` — [архитектура](docs/architecture.md), [требования к мебели](docs/furniture.md), [развитие](docs/product.md), [эксплуатация](docs/operations.md).
