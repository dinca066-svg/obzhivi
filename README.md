# Обживи — кабинет каталога мебели

Прототип: загрузка статичного GLB 2.0, 3D-просмотр, внешние габариты в миллиметрах, проверка масштаба, единая коррекция масштаба, поворот по осям, сохранение карточек в IndexedDB и экспорт ZIP с нормализованным GLB и JSON.

Поле `productUrl` хранит ссылку на конкретную комплектацию и входит в экспорт JSON. В карточках отображается кнопка «Посмотреть у продавца» с доменом магазина. Допускаются абсолютные HTTP(S)-ссылки без встроенных логина/пароля; переход открывается в отдельной вкладке. Старые карточки без ссылки продолжают работать. Проверка формата URL не подтверждает наличие товара или актуальность страницы продавца.

## Запуск

Node.js 22+; `npm ci`, `npm test`, `npm run build`, `npm run dev`. Локальный адрес: http://127.0.0.1:8781.

## Контракт модели

- Один товар и одна комплектация в одном самодостаточном GLB; текстуры внутри файла, максимум 50 МБ.
- glTF: метры, Y вверх; ширина X, глубина Z. Точка установки после нормализации — центр основания на полу.
- Указываются наружные размеры вместе с изголовьем, подлокотниками и прочими выступами, а не размер матраса.
- Проверяемая геометрия статична: без анимации, скиннинга и морфов. При несовпадении пропорций требуется исправить модель; растяжение по разным осям запрещено.
- Допуск прототипа: максимум из 5 мм и 1% отдельно для каждого габарита. Это проверка согласованности модели с карточкой, а не подтверждение фактических размеров изделия.
- Варианты отделки оформляются отдельными артикулами комплектации; автоматическое переключение KHR_materials_variants не реализовано.
- Экспорт model.glb содержит применённые трансформации. Сервис комнаты должен загружать его с внешним scale=[1,1,1]. В product.json размеры хранятся в миллиметрах.

## Хранение и границы прототипа

Страница `/planner.html` — примерка кровати в выбранной правой спальне. Использует товары из того же IndexedDB, поддерживает перетаскивание, поворот на 90°, стрелки/клавиатуру, расстояния до стен, привязку, сохранение положения в localStorage. Расстановка не сохраняется при пересечении стен или зоны открывания/подхода к двери. Проходы менее 600 мм подсвечиваются как ориентир; сторона изголовья исключена. Контур для проверки берёт максимум габаритов карточки и измеренной модели по каждой оси.

Комната 3050×5505 мм предварительно оценена по площади 16,79 м² и пропорциям выбранного контура 255×461 пикселей. Дверь и окна размечены приблизительно. Ввод размеров доступен, но статус комнаты остаётся `verified:false`: отдельного процесса подтверждения обмеров пока нет. Учитывается только эта прямоугольная комната и одна кровать; нет проверки радиаторов/высот окон и подбора шкафов. Сохранённые координаты — центр основания от верхнего левого внутреннего угла в миллиметрах, поворот по часовой стрелке на виде сверху. Для будущего Three.js это x/1000,z/1000 и rotation.y=-rotation*PI/180 при +Z вниз по плану.

Карточки и исходные файлы хранятся только в браузере на данном домене. Очистка данных сайта удаляет каталог; для резервной копии доступен экспорт каждой карточки. Общий серверный каталог, роли производителей, публикация товаров, расстановка в комнате, цены и оплаченный приоритет ещё не подключены. Учебные модели создаёт scripts/fixtures.mjs; они не являются изделиями производителя.

Следующий этап: API карточек, объектное хранилище исходных/нормализованных GLB, очередь серверной валидации и статусы draft/validated/published. Клиентскую проверку нельзя использовать как единственный контроль поступающих от поставщиков файлов.


## Поворот, дверь и фото товара

Кнопка поворота закреплена поверх центра кровати на плане и остаётся горизонтальной. Сама кровать перетаскивается за область вне кнопки. Клик на дверной проём открывает настройки: стена (left/right/top/bottom), петли (start/end вдоль стены), открывание (inward/outward), ширина и отступ. Для вертикальных стен отступ от верхнего угла, для горизонтальных — от левого. При смене на короткую стену отступ ограничивается её длиной. Старые сохранения получают left/start/inward.

Пересечения проверяются по сектору 90° открывающейся внутрь створки и отдельному прямоугольному подходу глубиной 600 мм внутри комнаты. При открывании наружу сектор находится снаружи, подход внутри остаётся. Внешний коридор не моделируется. Окна по-прежнему предварительные; их конфликт с переносом двери не проверяется.

Фото хранится отдельно от GLB и thumbnail: `photoDataUrl` (JPG/PNG/WebP до 8 МБ), `photoRemoved`. При выборе мебели 3D-скриншот никогда не подставляется вместо фотографии. Для ранее добавленной Shane по точному URL Маркета используется `public/photos/shane-seller.jpg` — неизменённое изображение из карточки продавца; источник: https://market.yandex.ru/card/krovat-shane-160kh200-dvuspalnaya-s-podyemnym-mekhanizmom-na-nozhkakh-obivka-velyur-belyy-velutto-soft-100-kant-chernyy/5971077429 . URL изображения: https://avatars.mds.yandex.net/get-mpic/19828547/2a0000019f6529c4188cc6b645d7c1d78b04/900x1200 . Пользовательское фото заменяет его; удаление не возвращает изображение по умолчанию. Фото входит в ZIP отдельным файлом и указано в `product.photo` экспортируемого JSON.


## Подготовка ракурсов комнаты

`/cameras.html` (также `/cameras`) открывается кнопкой «Сохранить и выбрать ракурсы» на плане. Читает только сохранённую расстановку и товар из IndexedDB текущего браузера; при отсутствии данных показывает переход к плану. Сцена пока содержит одну кровать, как и планировщик.

- Стены с реальными отверстиями по черновому плану, пол, потолок, две оконные конструкции и закрытая дверь; выбранные петли и направление открывания сохраняются в данных планировщика. Высоты потолка/двери/подоконника/окна редактируются. По умолчанию 2700/2100/850/1500 мм, все значения предварительные. Пересечения двери с окнами блокируют сборку.
- GLB загружается из карточки товара: сначала сохранённый quaternion и единый scale, затем выравнивание основания и центра, затем размещение в комнате. Координаты в метрах, Y вверх; угол сцены — минус поворот плана.
- Три композиции относительно кровати: фронтальная по продольной оси со стороны изножья, две диагонали из левого и правого углов со стороны изножья. Начальная высота 1400 мм, допускается подбор 1300/1500 мм. FOV ограничен 35–65°. Проверяется весь bounding box модели с 5% полем по краям и перекрытие архитектурой. Выбирается положение, затем FOV и смещение. Если композиция не помещается, карточка объясняет причину и не попадает в экспорт. Фронтальная камера при ручном перемещении остаётся на оси; ручные изменения не могут обрезать кровать или нарушать выбранную сторону диагонали.
- Камеры не могут попадать в стены, кровать или дверное полотно. Проход под камерой консервативно считается занятым по полному контуру кровати. Параметры хранятся в `obzhivi-bedroom-cameras-v1`; изменение расстановки или версии товара сбрасывает камеры. Изменения плана из другой вкладки блокируют экспорт до повторного открытия этапа.
- Экспорт: доступные композиции × RGB/depth/object-ID PNG, 1200×1600, `scene.json`, исходный GLB и README. Линейная глубина в пространстве камеры, 8 бит, white-near/black-far; параметры декодирования включены в JSON. Object-ID цвета без сглаживания, по палитре JSON; стены имеют разные ID, кровать свой, оба окна общий ID. Исходному GLB ещё нужно применить normalization из JSON. Полная Three.js-сцена в GLB пока не экспортируется.
- Генератор изображений не подключён. Нейтральный RGB-кадр — технический предпросмотр, не готовый дизайн. Стиль и единое задание для разных камер будут следующим этапом. Маски и глубина требуют поддержки выбранного генератора и сами по себе не гарантируют сохранение геометрии.

Горизонт камер закреплён: pitch=0 и roll=0. Композиция по высоте задаётся смещением окна проекции (viewOffset), без наклона оптической оси. Старые сохранённые наклоны автоматически переводятся в смещение; положение камеры и направление сохраняются. Экспорт включает viewOffset и projectionMatrix для одинаковой проекции RGB, глубины и масок.

Правила композиции имеют `rulesVersion=4`. Старые свободные камеры подбираются заново; совместимые изменения пользователя сохраняются. Дверь закрыта в RGB, depth, masks и на плане камер, состояние `doorState:closed` включено в экспорт. Настройки открывания двери в планировщике не изменяются.

Все кадры вертикальные, 3:4 (1200×1600). Проекция, область предпросмотра, миниатюры и экспорт используют одно соотношение сторон; после изменения формата композиции пересчитываются.

Визуальная балансировка: отдельный служебный рендер силуэта кровати 192×256, центр масс видимых пикселей. Смещение окна проекции по X и Y помещает этот центр в середину кадра с допуском 1,5% по каждой оси. После балансировки повторно проверяются полный контур модели и поля 5%. При необходимости FOV увеличивается в пределах 65°, положение мебели не меняется. Автоматическая балансировка применяется также при ручном перемещении камеры. Центр и метод входят в scene.json; slider вертикального смещения заменён автоматическим центрированием.


## Тумбы GRV в сцене

В комплект прототипа включены GLB пользователя и фото товара GRV YM-103724742948. Размеры из характеристик продавца: ширина 450, глубина 400, высота 470 мм. Единый масштаб модели задан по высоте; сетка имеет приблизительно 455 × 415 × 470 мм. `modelApproximate: true` отличает её от проверенного товара; пересечения учитывают максимум реальных и заявленных размеров. Пропорции сетки не растягиваются.

В layout.furniture сохраняются независимые экземпляры с productId, id, x/z в мм и поворотом по часовой стрелке на плане. Две тумбы можно добавить у изголовья, переместить, повернуть на 90° кнопкой на предмете или R, удалить по отдельности. Пересечения со стеной, дверью и мебелью блокируют сохранение.

Камеры rulesVersion 5 проверяют границы всего комплекта; визуальный центр считается по видимому силуэту мебельной группы. Перекрытие тумбы другой мебелью показано отдельно; оно не исправляется перемещением мебели. В ZIP — отдельные маски экземпляров, исходный GLB тумбы, габариты, нормализация, ссылка продавца и позиции. Seedream пока не подключён.


## Основной кадр со стенами и дверью

Правила камер версии 6 добавляют «Комната и дверь» как основной референс. Подбор проверяет полные границы мебели и двери с наличниками с полем 3%, минимум 2% площади кадра для двери и 85% видимости её проекции, две смежные стены не менее 3% кадра каждая и угол с вертикальным отрезком не менее 12% высоты. Видимость поверхностей проверяется служебными масками с учётом перекрытий. Камера остаётся внутри комнаты, горизонт и вертикали ровные, формат 3:4. Для общего кадра допускается FOV до 85°; мебельные ракурсы сохраняют предел 65°. Общая группа мебели и двери центрируется по проецируемым границам. Это широкий геометрический референс, а не крупный мебельный кадр.

Дверь закрыта, имеет контрастное полотно, наличники, филёнки и ручку на стороне, соответствующей петлям. Расстановка не изменяется подбором камер. При отсутствии подходящего общего кадра экспорт комплекта блокируется. В ZIP основной референс дополнительно назван `generation-input.png`, инструкция — `generation-guide.txt`, метаданные содержат `primaryGenerationCamera` и результаты проверки видимости. Остальные изображения служат дополнительными референсами. Эти эвристики не гарантируют сохранение геометрии генератором.


## Единый путь от плана квартиры

Главная `/` и `/start.html` открывают загрузку PDF/JPG/PNG/WebP (20 МБ), выбор страницы PDF, выделение прямоугольной спальни и проверку геометрии. PDF.js и его ресурсы размещены на самом сайте. Файл читается в браузере, исходник на сервер не отправляется. Есть пример реальной квартиры с предварительно размеченными комнатами; на произвольном файле контур задаёт пользователь, автоматического распознавания нет.

Масштаб: площадь + отношение сторон выделения; известная длина верхней стены + отношение сторон; либо две введённые длины. По одной площади длины не считаются достоверными: `verified:false` сохраняется даже после пользовательской проверки. Поддерживается одна прямоугольная спальня с одной дверью; сложные контуры и вся квартира в 3D пока не поддерживаются. Высота потолка, дверь (стена, отступ, размеры, петли, открывание), каждое окно (стена, отступ, ширина, подоконник, высота) проверяются перед переходом. Пересечение проёмов и выход за стены блокируют его.

Проект `obzhivi-plan-project-v1` хранит уменьшенное изображение, страницу, контур, калибровку, геометрию и высоты. При переходе новый project.id отделяет его от старой расстановки; планировщик использует новые размеры и не подставляет мебель из предыдущей комнаты. При сохранении мебели `sourceProjectId`, `planSource`, `heights` и `room.windows` попадают в layout. JSON экспорта включает источник, контур и способ расчёта. Явный пустой список окон означает отсутствие окон. Старые проекты без windows продолжают использовать прежнюю предварительную разметку.

`/planner.html` → `/cameras.html` сохраняют тот же контракт комнаты. Для окон на любой из четырёх стен используют общие `windowsFor` и `openingPlanPath`; 3D строится из `openingsFor`. Изменение высот или геометрии инвалидирует камеры. Переходы назад доступны в навигации. Каталог перенесён на `/catalog.html`; кровать Shane и тумба GRV включены в публикацию, поэтому доступны без предварительного импорта GLB в новом браузере. Карточки по-прежнему можно редактировать локально. Генерация Seedream не подключена: путь заканчивается подготовкой исходных кадров.
