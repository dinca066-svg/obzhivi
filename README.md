# Обживи — кабинет каталога мебели

Прототип: загрузка статичного GLB 2.0, 3D-просмотр, внешние габариты в миллиметрах, проверка масштаба, единая коррекция масштаба, поворот по осям, сохранение карточек в IndexedDB и экспорт ZIP с нормализованным GLB и JSON.

Поле `productUrl` хранит ссылку на конкретную комплектацию и входит в экспорт JSON. В карточках отображается кнопка «Посмотреть у продавца» с доменом магазина. Допускаются абсолютные HTTP(S)-ссылки без встроенных логина/пароля; переход открывается в отдельной вкладке. Старые карточки без ссылки продолжают работать. Проверка формата URL не подтверждает наличие товара или актуальность страницы продавца.

## Запуск

Node.js 22+; `npm ci`, `npm test`, `npm run build`, `npm run dev`. Локальный адрес: http://127.0.0.1:8781.

## Контракт модели

- Один товар и одна комплектация в одном самодостаточном GLB; текстуры внутри файла, максимум 50 МБ.
- glTF: метры, Y вверх; ширина X, глубина Z. Точка установки после нормализации — центр основания на полу.
- Указываются наружные размеры вместе с изголовьем, подлокотниками и прочими выступами, а не размер матраса.
- Проверяемая геометрия статична: без анимации, скиннинга и морфов. При несовпадении пропорций требуется исправить модель; растяжение по разным осям запрещено.
- Допуск прототипа: максимум из 5 мм и 1% отдельно для каждого габарита. Это проверка согласованности модели с карточкой, а не подтверждение фактических размеров изделия.
- Варианты отделки оформляются отдельными артикулами комплектации; автоматическое переключение KHR_materials_variants не реализовано.
- Экспорт model.glb содержит применённые трансформации. Сервис комнаты должен загружать его с внешним scale=[1,1,1]. В product.json размеры хранятся в миллиметрах.

## Хранение и границы прототипа

Карточки и исходные файлы хранятся только в браузере на данном домене. Очистка данных сайта удаляет каталог; для резервной копии доступен экспорт каждой карточки. Общий серверный каталог, роли производителей, публикация товаров, расстановка в комнате, цены и оплаченный приоритет ещё не подключены. Учебные модели создаёт scripts/fixtures.mjs; они не являются изделиями производителя.

Следующий этап: API карточек, объектное хранилище исходных/нормализованных GLB, очередь серверной валидации и статусы draft/validated/published. Клиентскую проверку нельзя использовать как единственный контроль поступающих от поставщиков файлов.
