# Эксплуатация прототипа

## Окружение

`KIE_API_KEY` — секрет production runtime Sites. Локально используется игнорируемый `.dev.vars` для Wrangler; `.env.local` — файл, куда владелец изначально вставил ключ. Оба исключены из Git. Не выводить ключи в логи, не добавлять VITE_/NEXT_PUBLIC_ префикс.

Sites project: `appgprj_6af4642b96348191ac30a713f507b485`. Binding D1 — `DB`, R2 — `BUCKET`. `.openai/hosting.json` содержит идентификатор и bindings. Публикация через Sites сохраняет исходный commit и отдельную сборку. GitHub — приватная копия исходников и документации; сам по себе push туда сейчас не публикует сайт.

## Миграции и тесты

После изменения `db/schema.ts`: `npm run db:generate`, проверить SQL, применить новую миграцию локально, затем сборка / тесты. Применённые миграции не редактировать. Sites применяет миграции к hosted DB при деплое.

`npm test` проверяет модель/масштаб, геометрию и проёмы, коллизии, камеры, разделение гостевых данных, уникальность платной отправки и обработку неопределённого результата. Внешний Kie в автоматических тестах подменяется. Реальная проверка проводится вручную явной генерацией с опубликованного сайта.

## Ошибки

- `generationReady:false`: проверить секрет и bindings; ключ не показывать в ответах API.
- `failed`: провайдер однозначно отказал или не удалось сохранить исходник. Проверить баланс, доступ к модели и параметры задачи в Kie.
- `unknown`: проверить provider task ID и журнал Kie перед новой отправкой. Не повторять автоматически: исходный запрос мог быть платным и успешным.
- Задача долго `queued/generating`: обновить состояние страницы; это не создаёт вторую задачу.
- Изображение не открывается через 14 дней: текущая версия хранит URL Kie, не копию результата.

Отзывы хранятся в таблице `feedback`, задачи — `generations`. Публичного endpoint для выгрузки всех отзывов нет. Для администраторского просмотра использовать доступ владельца к данным хостинга; отдельный кабинет команды запланирован.

## Проверка перед передачей

1. Новый анонимный браузер открывает `/` без sign-in.
2. Загрузка собственного плана или пример → спальня → подтверждение размеров и проёмов.
3. Кровать, поворот, тумбы, сохранение.
4. Основной кадр: две стены и закрытая дверь, горизонт ровный.
5. Выбор стиля → создание → ожидание → результат и ссылки продавцов.
6. Перезагрузка страницы сохраняет историю; другой сеанс не получает доступ к заданию по UUID.
7. Отзыв отправляется и подтверждается.

В текущем прототипе localStorage содержит только один активный проект. Встроенные товары доступны всем, локально добавленный GLB — только в браузере загрузки. Не обещать автоматическое распознавание БТИ или полную планировку квартиры.
