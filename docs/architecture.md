# От плана к дизайну

## Источник геометрии

Пользователь выбирает спальню: изображение не позволяет достоверно определить назначение комнаты. В первой версии интерфейс задаёт одну задачу: выбрать спальню. Для изображения или страницы PDF локальный алгоритм сохраняет длинные горизонтальные/вертикальные линии, соединяет небольшие разрывы и находит замкнутые почти прямоугольные области. Это предварительные предложения, не семантическое распознавание БТИ: площадь и проёмы алгоритм не читает, тип помещения не угадывает. Для встроенного примера используются две явно обозначенные заранее размеченные комнаты. Пользователь выбирает область кликом/тапом или с клавиатуры, при необходимости исправляет границы, затем задаёт площадь или размеры, уточняет дверь и окна. Если кандидатов нет, доступен ручной выбор двумя углами с видимым первым маркером. Сложные контуры не превращаются автоматически в комнаты.

Для площади A и пропорции r = ширина_пикселей / глубина_пикселей: ширина = sqrt(A*r), глубина = sqrt(A/r). Это оценка при условии отсутствия перспективных искажений и верного внутреннего контура. Одна площадь сама по себе размеров не определяет. Точные размеры пользователя приоритетнее оценки. Статус `verified:false` сохраняется: подтверждение в UI не заменяет обмер.

Локальный проект `obzhivi-plan-project-v1` содержит изображение, контур, калибровку, назначение, размеры, проёмы и UUID. Расстановка `obzhivi-bedroom-layout-v1` связана с UUID проекта. Смена проекта исключает перенос старой мебели в новую геометрию. Исходный план не отправляется на сервер.

## Сцена

Внутренние размеры плана — мм; Three.js / GLB — метры, Y вверх. Стены строятся с вырезами из списка проёмов. Размещённая мебель содержит productId и независимый instanceId, x/z, rotation. Проверка контура берёт максимум габаритов товара и измеренной модели. Пересечения стены, мебели и зоны двери блокируют сохранение.

Камеры привязаны к ревизии расстановки. Главный кадр «Комната и дверь» должен включать мебель целиком, две смежные стены, видимый угол и закрытую дверь. Вертикали и горизонт закреплены; для композиции используется optical shift. Формат 1200×1600. Если условия не выполнены, генерация недоступна, а мебель не перемещается ради кадра.

## Генерация

1. Пользователь выбирает стиль / пожелания и явно нажимает кнопку.
2. Браузер фиксирует RGB главной камеры и snapshot сцены, сохраняет UUID запроса до отправки.
3. Сервер создаёт строку задания с уникальным `(session_id, request_id)` до вызова платного API.
4. PNG сохраняется в R2; Kie получает временную ссылку (24 часа), защищённую случайным токеном. В D1 хранится только хеш токена.
5. Kie `seedream/5-5-image-to-image` получает один reference, prompt, формат 3:4, размер 2K. Глубина и маски экспортируются отдельно, но этому API не передаются.
6. Task ID сохраняется. Страница результата опрашивает сервер с увеличением интервала; сервер проверяет Kie. Повторный POST с тем же UUID возвращает то же задание.
7. Если исход отправки неоднозначен, статус `unknown`; автоматической повторной платной отправки нет. Нужна проверка Kie владельцем.
8. Результат отображается рядом с исходником; ссылки на товары берутся из snapshot, а не из распознавания сгенерированного изображения.

Промпт фиксирует мебель и архитектуру, но не гарантирует их сохранения. Автоматической проверки сходства результата в этой версии нет. Ссылка на результат хранится в D1, само изображение пока у Kie (14 дней). Пользователю предлагается сохранить его.

## Данные и доступ

| Данные | Хранилище | Доступ |
| --- | --- | --- |
| План, разметка, расстановка, камеры | localStorage | Этот браузер |
| Локально загруженные модели | IndexedDB | Этот браузер |
| Встроенная мебель | Статические assets | Посетители сайта |
| Сеанс, задания, snapshot, отзывы | D1 | Сервер; задания только владельцу сеанса |
| Исходные кадры | R2 | Гостевой сеанс или временная ссылка Kie |
| API-ключ | Секрет окружения Worker | Только сервер |

Гостевой идентификатор — случайный HttpOnly cookie, SameSite=Lax, Secure на HTTPS, срок 90 дней; D1 хранит только его хеш. Это анонимный тест, не полноценная учётная запись. После удаления cookies история недоступна. Мутации проверяют Origin; сервер не принимает произвольный URL исходного изображения.

## API

- `GET /api/config` — готовность генерации и стили, без секретов.
- `POST /api/session` — создать или продолжить гостевой сеанс.
- `POST /api/generations` — создать/вернуть задание по requestId.
- `GET /api/generations` — до 50 последних заданий текущего гостя.
- `GET /api/generations/:id` — состояние и результат.
- `GET /api/generations/:id/reference` — исходник владельцу сеанса.
- `GET /api/reference/:id?token=...` — временный исходник для провайдера.
- `POST /api/feedback` — отзыв, необязательно связанный со своим заданием.
